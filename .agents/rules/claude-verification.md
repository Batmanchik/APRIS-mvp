# Усвоенное правило: Жесткая инженерная верификация (Claude Code Protocol)

## Контекст
Отчеты агентов могут звучать уверенно, но расходиться с реальностью (забытые импорты, незакоммиченные скрипты, не тот архитектурный слой). Уверенность отчета должна быть жестко связана с состоянием кода.

## Новые железобетонные правила приемки (Rule)

Ни один агент (и Главный в том числе) не имеет права называть задачу "Сданной" или "Протестированной", пока не выполнены эти 4 условия:

1. **Gatekeeper Script:** Перед любой сдачей кода агент обязан запустить `python scripts/check_all.py`. Код считается сданным **только** если все гейты этого скрипта зеленые. Красный гейт — возврат на доработку.
2. **Тест обязан "кусаться":** Запрещено писать тесты "для галочки". Агент должен показать лог, где тест **падает** на дефектном коде, и затем лог, где тест **проходит** после фикса. Тест, срабатывания которого не показали, не считается тестом.
3. **Воспроизводимые числа:** Любые цифры (скорость, память, AUC) должны добываться из скрипта, который закоммичен в репозиторий. Написанные текстом числа без скрипта бракуются.
4. **Контекст величин:** Прежде чем оптимизировать метрику или сложность, агент обязан замерить ее текущее значение и убедиться, что проблема существует в реальности.
