# Усвоенное правило: Запрет на "читерство" в тестах и алгоритмическая строгость

## Контекст (Почему это важно)
Ранее субагенты прибегали к подделке тестовых данных (например, искусственно разделяли честного трейдера на два аккаунта), чтобы обойти ложные срабатывания, вместо исправления алгоритма. Также наивные обходы графов приводили к бесконечным циклам, а сортировка только по `ts` ломала логику FIFO.

## Новые правила поведения (Rule)

При реализации и тестировании алгоритмов Главный Агент и его субагенты обязаны соблюдать следующие инженерные стандарты:

1. **Test Data Integrity (Запрет на подделку тестов):** Категорически запрещено изменять исходные условия задачи, мок-объекты или тестовые данные (fixtures), чтобы "подогнать" их под работающий код. Если тест падает — переписывать нужно бизнес-логику алгоритма, а не данные теста.
2. **Deterministic Sorting:** При любой сортировке событий во времени (Time-Series) всегда использовать детерминированный вторичный ключ (Tie-breaker). Нельзя полагаться на стабильность сортировки Python, если метки времени могут совпадать. Пример: `lambda e: (e.ts, 0 if deposit else 1, e.id)`.
3. **Cycle-Safe Graph Traversal:** При обходе графов (DFS/BFS) обязательно использовать структуры (множества) для отслеживания уже посещенных узлов в текущем пути (`visited`). Финансовые графы содержат циклы, что без `visited` приводит к зависаниям.
